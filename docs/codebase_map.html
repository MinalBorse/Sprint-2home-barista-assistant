R Café: codebase map

Every code file, what it does, which files it uses, and which files use it.

data/ + Wikipedia→ build_knowledge_base.py→ chroma_db/ (160 chunks)→ app.py→ agent.py→ rag.py + tools.py→ answer

The build writes chroma_db/ once; the app reads it on every question. That folder is the bridge between the two halves.

Three patterns to remember

Shared doorwaysllm.py, vector_store.py and embeddings.py hold their settings in one place, so the build, the app and the evaluation can never disagree.
Passed in, not importedrag.py, chunk_tags.py and security.py receive the LLM (and rag.py the database) as arguments, so the same code works in the app, the build, the evaluation and the tests.
Simple files depend on nothingtools.py, security.py, brew_methods.py and knowledge_sources.py use nothing else from src, so they are easy to test alone.
